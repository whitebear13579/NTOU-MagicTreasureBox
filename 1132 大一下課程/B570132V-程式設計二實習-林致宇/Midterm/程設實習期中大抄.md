## Binary Search Template
### For-Loop
帶左右界版本：
```cpp=
inline signed solve(){
    vi uwu(10,0);
    int t = 0;
    for ( int i = 0 ; i < 10 ; i++ ){
        uwu[i] = nextint();

    }
    t = nextint();
    int ans = -1 ,l = 0 , r = 9;
    while ( l <= r ){
        int mid  = ( l + r ) >> 1;
        if ( uwu[mid] == t ){
            ans = mid;
            break;
        }else if ( uwu[mid] < t ){
            l = mid + 1;
        }else{
            r = mid - 1;
        }
    }
    cout << ans << "\n";
    return 0;
}
```

```cpp=
inline int binary ( int l , int r , int tar , const vi &owo ){
    int mid  = ( l + r ) >> 1;
    if ( l > r ) return -1;
    
    if ( owo[mid] == tar ) return mid;
    else if ( owo[mid] < tar ){
        return binary( mid+1, r, tar, owo );
    }else{
        return binary( l, mid-1, tar, owo );
    }
}
```

```cpp=
void swpNode( shared_ptr<Number> a , shared_ptr<Number> b ){
    //處理 A 的前一項 
    if ( a->previous != nullptr ) a->previous->next = b;
    b->previous = a->previous;
    //處理 B 的後一項
    a->next = b->next;
    if ( b->next != nullptr ) b->next->previous = a;

    a->previous = b;
    b->next = a;

    if ( a->previous == nullptr ) head = a;
    else if ( b->previous == nullptr ) head = b;
```

## Smart Pointer Usage
`unique_ptr<T>`：每個物件都獨一無二。這種類型的指標不能複製，只可移動。結束時自動釋放所管理的物件。
`shared_ptr<T>`：與一般指標相同，內部維護一個 reference count，最後一個引用者離開作用域後會自動釋放記憶體。
`weak_ptr<T>`：內部沒有維護 reference count 的 shared_ptr。可以利用 weak_ptr 來避免 cyclic reference 造成的記憶體洩漏。

### 初始化
```cpp=
auto up = std::make_unique<T>(......);    // unique_ptr<Foo>
auto sp = std::make_shared<T>(......);    // shared_ptr<Foo>

// 直接 new
std::unique_ptr<T> up2(new T(......));
```

### 移動與複製
```cpp=
// unique_ptr 只能移動，不能複製
std::unique_ptr<T> upMove = std::move(up);
std::shared_ptr<T> spMove = std::move(sp);

// shared_ptr 可直接複製，會自動增加引用計數
std::shared_ptr<T> spCopy = sp;
```

### 其他操作
`p.get()`：取回底層指標（切記！不要！手動 delete！）
`p.reset()`：釋放目前管理的物件（相當於 delete + 指標歸空）
`p.release()`：僅 unique_ptr，交出所管理物件的原始指標並歸空，不會自動刪除
:::warning
- 避免循環引用導致 cyclic reference 的 memory leak。
- 不要手動呼叫 delete，混用原始指標 delete 與智慧指標會導致雙重釋放或 undefined bahavior。
:::
